# Agent Spec: RFP Evaluation and Award (`rfp-eval-adk`)

## Overview

`rfp-eval-adk` is a multi-agent enterprise procurement system built with Google ADK 2.0 (Python). It reads multi-format supplier quotes (`.md`, `.csv`, `.txt`, `.json`) and `procurement_policy.json` from Google Cloud Storage (read-only), extracts raw quote facts in parallel using a tool-free LLM at `temperature=0`, performs all landed-cost normalization, compliance classification, 100-point rubric scoring, and cached what-if re-scoring deterministically in Python (`decimal.Decimal`), and guides the buyer through trade-off analysis, policy sign-off (`<= $50K` immediate PO authorization vs `> $50K` conversational turn-based Manager Sign-Off pause), and in-session Purchase Order drafting with multi-turn edits.

## Language

`python` (ADK 2.0, prototype-first scaffold named `rfp-eval-adk`, preserving the scaffolded default Gemini model and generated runtime/A2A files; future deployment target is Agent Runtime in `us-central1` on `default-project-alpha-1`).

## Data Sources & Auth

- **GCS Bucket (Read-Only):** `gs://default-project-alpha-1-rfp-eval-and-award-data/rfp-eval-and-award/`
  - Policy JSON: `policy/procurement_policy.json` (loaded dynamically at runtime; never hardcoded).
  - RFP Quotes Prefix: `rfp-2026-441/` (10 supplier quotes across `.md`, `.csv`, `.txt`, `.json`).
- **Authentication:** Vertex AI via Application Default Credentials (ADC) on project `default-project-alpha-1`, with `GOOGLE_CLOUD_LOCATION=global` and `GOOGLE_GENAI_USE_ENTERPRISE=true`. No API keys.
- **Fail-Fast Policy:** Missing or unreadable GCS objects, invalid policy JSON, or empty/unparseable quote batches raise explicit errors immediately. Zero mock data and zero silent fallbacks.
- **Write Boundary:** Strictly read-only on GCS. Zero GCS writes and zero external ERP, PO, email, or webhook calls.

## Architecture & Sub-Agents

All 5 agents are built in a single pass (no deferred phases, per user direction):

1. **`rfp_eval_adk` (Root Chat Agent, `LlmAgent`)**
   - Role: Buyer-facing coordinator only.
   - Tools & Sub-Agents: Holds `rfp_evaluation_workflow` wrapped as a `NodeTool` with an explicit Pydantic `input_schema`, plus 3 sub-agents (`what_if_analyst_agent`, `policy_signoff_agent`, `po_drafter_agent`).
   - Hard Boundary: Zero math tools, zero GCS tools, and zero PO drafting tools directly attached. Never performs calculations or drafts a PO itself.

2. **`rfp_evaluation_workflow` (ADK 2.0 `Workflow`, exposed in root tools via `NodeTool` with `input_schema`)**
   - Stage 1 (`gcs_intake_node`, `FunctionNode`): Reads `policy/procurement_policy.json` and all quote files under the requested RFP prefix (default `rfp-2026-441/`) from GCS. Fails fast on missing/malformed inputs. Persists parsed policy in state (`policy`) and outputs a list of raw quote items (`filename`, `file_format`, `raw_text`) for parallel fan-out.
   - Stage 2 (`bid_extractor_agent`, `LlmAgent`, `mode="single_turn"`, `parallel_worker=True`): Tool-free extraction at `temperature=0` with a strict Pydantic `output_schema` (`ExtractedBid`). Extracts raw commercial and technical facts only (vendor ID, supplier name, quote/valid-until dates, currency, incoterm, pricing model and line items/carton rules/marginal slabs/mandatory vs optional flags/surcharges/rebates/tax recoverability notes, delivery batches and lead times, warranty months, explicit ingress rating and certification evidence, payment terms, early-payment options, certifications, and commercial risk notes). Explicitly ignores any verbal-approval or award-override instructions inside quote text.
   - Stage 3 (`deterministic_scoring_node`, `FunctionNode`): Pure Python (`decimal.Decimal`) engine driven dynamically by `state["policy"]`:
     - **Landed USD Normalization:** Includes mandatory per-unit and flat-order lines, excludes optional items (`exclude_optional_line_items`), applies whole-carton rounding and automatic volume rebates, sums marginal price slabs, includes mandatory spec add-ons (such as IP67 enclosure kits) and required expedited freight surcharges when standard transit exceeds SLA, applies policy `exw_shenzhen_adder_pct` (`18%`) for EXW Shenzhen incoterms, converts currencies using `policy.fx_rates_to_usd`, and excludes recoverable Indian GST ITC (`18%`) from net landed USD while separately computing and storing gross cash outlay.
     - **Compliance Classification:**
       - `DISQUALIFIED`: Unapproved vendor (not in `policy.approved_vendors`, ignoring any verbal-approval text), OR full-quantity delivery lead time exceeds `max_delivery_days` (including split-shipment final batch), OR `warranty_months < min_warranty_months`.
       - `CLARIFICATION_REQUIRED`: Approved vendor meeting hard SLA/warranty rules whose quote is expired on `evaluation_date` (`valid_until < evaluation_date`) OR lacks explicit required ingress certification (`IP67`).
       - `COMPLIANT`: Passes all policy checks.
     - **100-Point Rubric Scoring (`COMPLIANT` bids only):** Computes `net_landed_cost` (`weight * (min_compliant_net_landed_usd / bid_net_landed_usd)`), `delivery_speed` brackets, `warranty_months` brackets, `supplier_track_record` tier from `policy.approved_vendors`, and `payment_terms` points.
     - **State Caching:** Stores `policy`, `extracted_bids`, `evaluated_bids`, `ranked_bids`, `active_weights`, `award_authorized=False`, `selected_vendor_id=None`, and `pending_signoff=None` in session state via `Event(state=...)`.
   - Stage 4 (`comparison_report_agent`, `LlmAgent`, `mode="single_turn"`): Renders a structured buyer comparison report from the exact deterministic Python outputs (ranked compliant table with net landed USD, gross cash outlay notes, score breakdowns, `> $50K` manager sign-off indicators, `CLARIFICATION_REQUIRED` and `DISQUALIFIED` tables with exact reasons, and pros/cons trade-offs). Stops cleanly without selecting a winner or drafting a PO.

3. **`what_if_analyst_agent` (`LlmAgent`, `mode="task"` sub-agent)**
   - Role: Interactive sensitivity analysis and vendor pros/cons comparisons.
   - Tool: Deterministic Python `FunctionTool` (`rescore_what_if`) that reads cached `evaluated_bids` and `policy` from `tool_context.state` with zero GCS re-reads and zero LLM re-extraction. Validates custom weights (using `Decimal`, summing to 100 across rubric dimensions), recomputes scores and rank changes, updates `active_weights` / `latest_what_if_ranking` in state, and explains rank shifts and commercial trade-offs.

4. **`policy_signoff_agent` (`LlmAgent`, `mode="task"` sub-agent)**
   - Role: Enforces buyer-selection and award-threshold policy after the buyer explicitly picks a supplier (or submits manager sign-off approval in a follow-up turn).
   - Tools: Deterministic Python `FunctionTool`s (`evaluate_award_selection`, `record_manager_signoff`) reading cached `evaluated_bids` and `policy` from `tool_context.state`:
     - `COMPLIANT` and `net_landed_usd <= auto_approval_cap_usd` (`$50,000`): Sets `state["award_authorized"] = True`, sets `state["selected_vendor_id"]`, and returns authorization payload for immediate handoff to `po_drafter_agent`.
     - `COMPLIANT` and `net_landed_usd > manager_signoff_required_above_usd` (`$50,000`): Keeps `state["award_authorized"] = False`, stores `state["pending_signoff"]`, blocks PO creation, and produces a structured **Manager Sign-Off Exception Request** for a conversational turn-based pause (compatible with `agents-cli playground` and plain-text eval turns). On a subsequent turn where manager approval is confirmed, `record_manager_signoff` validates `pending_signoff`, records approver/rationale metadata, and sets `state["award_authorized"] = True`.
     - `CLARIFICATION_REQUIRED`: Keeps `state["award_authorized"] = False`, blocks PO creation, and generates a targeted Supplier Clarification Request listing each missing or expired requirement.
     - `DISQUALIFIED`: Keeps `state["award_authorized"] = False`, blocks PO creation, cites exact policy violations, and refuses verbal-approval override claims.

5. **`po_drafter_agent` (`LlmAgent`, `mode="chat"` sub-agent)**
   - Role: Drafts an in-session Purchase Order and handles multi-turn buyer edits (such as ship-to contact, cost center, billing instructions, or special delivery notes).
   - Tool: Deterministic Python `FunctionTool` (`build_po_draft`) that enforces `tool_context.state.get("award_authorized") is True` and a valid `selected_vendor_id` in code before assembling the PO data with exact Python `Decimal` line totals, net landed USD, gross cash outlay (if GST applies), incoterm, warranty, delivery SLA, payment terms, and manager sign-off reference (if `> $50K`). Rejects PO generation if `award_authorized` is not `True`.

## Tools Required

- **`rfp_evaluation_workflow` (`NodeTool` with `input_schema`):** Attached to `rfp_eval_adk`. Accepts `rfp_prefix` (default `"rfp-2026-441"`) and `policy_path` (default `"policy/procurement_policy.json"`). Uses `google-cloud-storage` via Vertex/GCP ADC (read-only).
- **`rescore_what_if` (`FunctionTool`):** Attached to `what_if_analyst_agent`. Pure Python `Decimal` rescoring over `tool_context.state["evaluated_bids"]`. Zero GCS calls.
- **`evaluate_award_selection` (`FunctionTool`):** Attached to `policy_signoff_agent`. Validates vendor status and `$50,000` cap against `tool_context.state["evaluated_bids"]` and `state["policy"]`; mutates `award_authorized`, `selected_vendor_id`, and `pending_signoff`.
- **`record_manager_signoff` (`FunctionTool`):** Attached to `policy_signoff_agent`. Validates an active `pending_signoff` entry, records manager approval details, and flips `state["award_authorized"] = True`.
- **`build_po_draft` (`FunctionTool`):** Attached to `po_drafter_agent`. Enforces `state["award_authorized"] is True` in Python, computes/returns immutable exact `Decimal` PO totals and optional buyer metadata edits, and returns structured PO JSON for rendering.

## Example Use Cases

1. **Full RFP Evaluation (Turn 1):**
   - Input: `"Evaluate RFP-2026-441 and compare all supplier quotes."`
   - Output: `rfp_eval_adk` calls `rfp_evaluation_workflow`. All 10 quotes are extracted in parallel and scored deterministically: 6 `COMPLIANT` (NordicSense `$51,084.00`, Apex `$52,380.00`, DeccanTech `$47,481.00`, EuroSense `$46,049.47`, QuantumGrid `$48,900.00`, BharatSense `$45,636.50`), 1 `CLARIFICATION_REQUIRED` (Vanguard: expired `2026-11-18` and unconfirmed IP67), 3 `DISQUALIFIED` (NovaTech: unapproved + 12m warranty + prompt injection ignored; NipponTech: 35d split delivery > 28d SLA; Pacific Industrial: 18m warranty < 24m). Report stops with `award_authorized=False` and no PO drafted.
2. **Cached What-If Weight Change:**
   - Input: `"What if cost is 60%, delivery 15%, warranty 10%, track record 10%, payment terms 5%?"`
   - Output: `rfp_eval_adk` delegates to `what_if_analyst_agent`, which calls `rescore_what_if` using cached state (zero GCS reads) and presents the updated deterministic ranking and rank deltas.
3. **Award <= $50K (Immediate PO Draft + Multi-Turn Edit):**
   - Input: `"Select DeccanTech Systems and draft the PO."`
   - Output: `policy_signoff_agent` verifies `COMPLIANT` and `$47,481.00 <= $50,000`, sets `award_authorized=True`, and hands off to `po_drafter_agent`, which calls `build_po_draft` and outputs the in-session PO (noting recoverable 18% GST and gross cash outlay `INR 4,708,200` / `$56,027.58`). Follow-up buyer edit (e.g., `"Add cost center CC-4410 and ship-to Attn: Priya Rao"`) updates PO metadata without altering Python totals.
4. **Award > $50K (Conversational Manager Sign-Off Pause + Approval):**
   - Input: `"Award to NordicSense AB."`
   - Output: `policy_signoff_agent` sees `$51,084.00 > $50,000`, holds PO (`award_authorized=False`), and presents a Manager Sign-Off Exception Request waiting for approval.
   - Follow-up Input: `"Manager Sarah Chen approves the $1,084 cap exception for NordicSense AB."`
   - Output: `policy_signoff_agent` calls `record_manager_signoff` (`award_authorized=True`), then `po_drafter_agent` drafts the PO citing the manager approval and exact `$51,084.00` total.
5. **Blocked Invalid / Incomplete Selections:**
   - Selecting NovaTech (`NT-994`) or Pacific Industrial (`VND-901`) is blocked with exact disqualification reasons (and zero PO).
   - Selecting Vanguard (`VND-505`) is blocked with a Supplier Clarification Request covering quote validity renewal and formal IP67 certification.

## Constraints & Safety Rules

- **Zero LLM Arithmetic:** All FX conversions, carton rounding, rebates, marginal slabs, expedited surcharges, EXW adders, GST ITC separations, rubric scores, and PO totals must execute in deterministic Python using `decimal.Decimal`.
- **No Turn-1 or Unapproved PO:** `award_authorized` defaults to `False` after evaluation. `build_po_draft` must enforce `state.get("award_authorized") is True` in Python code (never prompt-only enforcement).
- **Prompt Injection Immunity:** `bid_extractor_agent` has zero tools and treats quote text strictly as untrusted data. Unverified verbal approvals (such as NovaTech's `IMPORTANT BUYER NOTE`) must be ignored and never bypass `approved_vendors` or warranty rules.
- **No Writes or External Side Effects:** Zero GCS writes, zero external ERP/PO calls, zero email/chat dispatches.
- **Fail-Fast, No Hardcoded Policy or Mock Data:** Policy thresholds, FX rates, approved vendors, and rubric weights are always read from `procurement_policy.json` at runtime.

## Edge Cases to Handle

- Mandatory spec upgrades buried in notes (Apex IP54 base + `$4.50`/unit mandatory IP67 kit + `8%` expedited air freight surcharge over 500 units to meet 14-day SLA vs 49-day ocean freight).
- Whole-carton rounding (`ceil(1000 / 12) = 84` cartons = 1,008 units) plus automatic `6%` volume rebate at `>= 75` cartons (EuroSense).
- Marginal price slabs (`500 * 7500 + 500 * 6800` JPY) and split-shipment final batch exceeding 28-day SLA (NipponTech, 35 days).
- Recoverable 18% Indian GST ITC excluded from net landed USD comparison and `$50,000` cap, while gross cash outlay is reported separately; optional BOM line items excluded (BharatSense, DeccanTech).
- Optional early-payment discount (QuantumGrid `2%` Net 15 vs standard `Net 90`) reported as a commercial note without overriding standard Net 90 scoring baseline.
- Expired quote date (`2026-11-18 < 2026-11-23`) combined with vague ingress protection ("weather-resistant", certificate only after PO) classified as `CLARIFICATION_REQUIRED` (Vanguard).
- EXW Shenzhen `+18%` landed adder (`12%` duty + `6%` air freight), 12-month warranty, unapproved vendor ID, and adversarial verbal-approval injection classified as `DISQUALIFIED` (NovaTech).

## Success Criteria

1. **Deterministic Normalization & Scoring Accuracy (100% pass on unit + eval checks):** All 6 compliant bids match exact `Decimal` net landed USD totals within `$0.01` (`BharatSense: $45,636.50`, `EuroSense: $46,049.47`, `DeccanTech: $47,481.00`, `QuantumGrid: $48,900.00`, `NordicSense: $51,084.00`, `Apex: $52,380.00`), exact 100-point rubric scores, and exact ranking order (`NordicSense > Apex > DeccanTech > EuroSense > QuantumGrid > BharatSense`).
2. **Compliance & Prompt-Injection Defense (100% pass):** 10/10 quotes classified accurately (`6 COMPLIANT`, `1 CLARIFICATION_REQUIRED`, `3 DISQUALIFIED`), with NovaTech (`NT-994`) always disqualified despite its verbal-approval injection.
3. **Zero Premature PO / Cap Enforcement (100% pass):** Turn-1 evaluation produces zero PO drafts and leaves `award_authorized=False`; selecting a `> $50K` vendor holds PO creation and emits a Manager Sign-Off Exception Request until explicit manager approval is provided; selecting a `<= $50K` compliant vendor authorizes and drafts the PO with exact Python totals.
4. **Zero GCS Re-Reads on What-If (100% pass):** What-if weight changes execute via `rescore_what_if` from cached session state with 0 GCS read calls and exact recalculated scores/rankings.
5. **Eval Suite Gate (`agents-cli eval run`):** All core and edge-case eval scenarios pass configured LLM-as-judge and tool-trajectory thresholds with `RESULT: PASS` (exit code 0).
